Why this is the near-certain one: RNAAS checks that a note is appropriate astronomy and properly formatted. It doesn't ask for novelty or completeness, and accepted notes are typically online within 72 hours. It still carries the AAS name, a DOI and an ADS entry, which is real, citable proof that the work exists.

Honest caveat: moderation is not a rubber stamp. The editor can decline a note that reads as out of scope or as an unfounded theory. This note is a controlled experiment with public code and conservative claims, which is the kind RNAAS publishes.

The note

Keeping a “None of the Above” Hypothesis Matters More Than Planning With It: A Controlled Test for Transient Follow-Up

Information-driven follow-up planners for astronomical transients usually assume the event belongs to one of a fixed set of classes. We test, in a controlled toy problem, what happens when it does not. Across simulated fading transients ( seeds), a closed-world expected-information-gain planner was confidently wrong on of events from a withheld class. Adding an explicit unmodeled hypothesis h₀, represented by a Gaussian process, to the posterior largely removes this failure. Choosing measurements with h₀ in the planning objective did not add a clear further benefit: randomly timed measurements scored with the same open-world posterior flagged of withheld events, against for the open-world planner. Model-inadequacy detection therefore has to be designed into the planning objective explicitly, not expected as a by-product of information gain.

what this means for the main paperThis result complicates hypothesis H3 as currently framed. Simply including h₀ in the planner's predictive mixture did not make it a better inadequacy detector than random timing. That is the argument for the explicit adequacy term β·I(Z; Y) and the preservation mode in the Phase 2 utility. Phase 2 has to show that that term closes the gap, and this note is the honest baseline it must beat.

Submission steps

  • Run the controlled experiment at full scale (3 seeds × 1,000 events) and generate every number from result files.
  • Draft in AASTeX v7 within the limits: ≤150-word abstract, one table.
  • Replace the author placeholders in research/papers/rnaas/note.tex: name, ORCID, affiliation, email, any co-authors. Single-author notes should use “I”, not “we”.
  • Add a LICENSE file to the repository, tag a release, and mint a Zenodo DOI. Cite it in Code availability.
  • Rebuild: python -m research.figures.rnaas_note, then bash research/papers/rnaas/build.sh. Check the editorial word count.
  • Submit at aas.msubmit.net. After acceptance, post to arXiv (astro-ph.IM) and add the DOI to this site.
